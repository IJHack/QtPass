Detailed Description

Dialog for creating a password entry or editing an existing one.

The first line is the password, with a generator beside it; below it are one field per template line when templates are in use, and a free text box for everything else. For an existing entry the dialog asks the backend to Show() it and fills the fields when the content arrives. On OK it puts the entry together again and calls Pass::Insert(), then stays open with its fields locked until the backend reports: it closes on Pass::finishedInsert() and gives the fields back with the reason on Pass::insertFailed(), so a failed save never loses what was typed.

◆ accept()

void PasswordDialog::accept ( )
override

OK: for a new entry, resolve and check the name first and stay open when it is not usable; then insert the entry and close as accepted only once the insert has succeeded.

The insert is asynchronous. Until it reports back the dialog stays open with its fields locked; when it fails (a missing recipient key, an unusable .gpg-id, a refused path) the fields come back with what was typed and the reason is shown, instead of the entry being lost with the closed dialog.

Let a new entry be named inside the dialog: a folder picker over the store's folders and a name field, instead of a separate prompt.
