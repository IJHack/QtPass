Detailed Description

Represents the parsed contents of a password file.

Splits the file into a password line, named key/value fields, and remaining data. Use FileContent::parse to construct an instance.

◆ getOtpUri()

auto FileContent::getOtpUri ( ) const -> QString
nodiscard

The entry's raw one-time password configuration, if it has one.

Looked up in this order:

  1. the value of the first field whose name satisfies isOtpFieldName();
  2. the first bare otpauth:// line in the body, which is how the pass-otp extension stores it;
  3. the value of the first OTP: line that was not promoted to a named value, which is what happens when the template does not list OTP.

The string is returned verbatim and is not validated here: it may be an otpauth:// URI or a bare base32 secret. Totp::parse() does the validation.

Returns
The OTP configuration string, or an empty string when the entry has none.

auto FileContent::getPasswordForDisplay ( ) const -> QString
nodiscard

Like getPassword but empty when the password line is itself an otpauth URI.

pass otp insert writes the URI as the entry's only line, so it lands in the password position. It is a shared secret, not a password: it must never be rendered or placed on the clipboard. getPassword() still returns it so the edit dialog round-trips the file unchanged.

Returns
The password, or an empty string when it is an otpauth URI.

auto FileContent::parse ( const QString & fileContent,
const QStringList & templateFields,
bool allFields,
const std::function< bool(const QString &)> & alsoField = {} ) -> FileContent
static

parse parses the given fileContent in a FileContent object. The password is accessible through getPassword. The named value pairs (name: value) are parsed and depending on the templateFields and allFields parameters accessible through getNamedValues, getRemainingData or getRemainingDataForDisplay.

Parameters
fileContentthe file content to parse.
templateFieldsthe fields in the template. Fields in the template will always be in getNamedValues() at the beginning of the list in the same order.
allFieldswhether all fields should be considered as named values. If set to false only templateFields are returned in getNamedValues().
alsoFielda field besides those, by its trimmed name: a secret the panel hides, which must not be left in the remaining text in plain view. Empty: none.
Returns
A FileContent instance with password, named values, and remaining data populated from the parsed input.

◆ kMaxDisplayLines

int FileContent::kMaxDisplayLines = 10000
staticconstexpr

Most lines of remaining text getRemainingDataForDisplay() gives.

The text browser makes a block, with its layout, per line. Past this many the display text ends with one line saying how many more there are; getRemainingData() keeps them all, so saving loses nothing. The edit dialog uses the same number for the whole entry (password and fields included) and does not load one with more lines.

◆ kMaxNamedFields

int FileContent::kMaxNamedFields = 1000
staticconstexpr

Most named fields parse() takes from one entry.

Every field becomes a row of widgets in the display panel. An entry is compressed before it is encrypted, so a small one in a shared store could decompress into millions of "a: b" lines within the plaintext limit; lines past this many fields stay in the remaining text. They are still looked at for an OTP configuration, as fields would be.
