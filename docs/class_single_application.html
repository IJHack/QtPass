Detailed Description

QApplication subclass enforcing single-instance behavior via IPC. Detects whether another instance with the same unique key is running and enables forwarding messages (e.g., command-line arguments) to it.

SingleApplication::SingleApplication ( int & argc,
char * argv[],
QString uniqueKey )

Construct a SingleApplication with a unique instance key.

Takes the lock file for the key (lockPathFor()). Whoever holds it is the instance that listens; a lock left by a crashed instance is stale and taken over. When another live instance holds it this one probes the socket and, if it answers, becomes a secondary: isRunning() turns true.

Parameters
argcReference to program argc forwarded to QApplication.
argvProgram argv forwarded to QApplication.
uniqueKeyName of the local socket: a full path (see privateKey()) or a bare name, which Qt puts in the temporary folder.

◆ claimOrFollow()

void SingleApplication::claimOrFollow ( )
private

Take the lock and listen, or become the lock holder's secondary.

A free lock, or one left by a crashed instance, is taken and this instance listens (becomePrimary()). A lock held by a live instance makes this one wait for that instance's socket (waitForPeer()). A lock that cannot be taken at all leaves this instance without IPC.

◆ privateKey()

auto SingleApplication::privateKey ( const QString & base) -> QString
static

The key to construct with: a socket path in a folder only this user can write to (see privateKeyIn()).

The socket used to be named after the login name in the shared temporary folder, next to a shared-memory segment and its semaphore. Another local user could create those first and keep QtPass from starting (scan ANT-2026-1JUBRKLZ). The folder is QStandardPaths::RuntimeLocation, which Qt refuses when another user owns it. On Windows the key stays base: a pipe name cannot hold a path. Call it before the application object exists.

Parameters
basePer-user name, such as the login name plus "QtPass".
Returns
The key for the constructor.

◆ serverRunsAsThisUser()

auto SingleApplication::serverRunsAsThisUser ( const QLocalSocket & socket) -> bool
static

Whether the server socket is connected to runs as this user.

On Windows a named pipe's name is machine-wide: another user's session could open the pipe of the key first, and a launch would then forward its command line there and exit without a window. So the server's process is looked up (GetNamedPipeServerProcessId()) and its token's user compared with this process's; anything that cannot be checked counts as someone else's. Elsewhere the socket sits in a folder only this user can open (privateKey()), and this is always true.

Parameters
socketA socket connected to the key.
Returns
true when the server is this user's.
