Detailed Description

Static helpers that have no better home: setting up the process and the Git environment the way pass does, finding binaries and the default store, path and URL handling, and file operations that refuse to follow links.

Nothing here keeps state apart from the cached process environment, and nothing depends on a widget or a model. Store-boundary checks live in PathValidator, SSH agent discovery in SshAuthSock and template files in TemplateIO.

Set up the process the way pass sets up its own, before anything runs git or gpg or writes into the store.

Clears the variables that point git at another repository (GIT_DIR, GIT_WORK_TREE and the rest pass clears), and on Unix gives the processes QtPass starts (git, gpg, pass) the umask from PASSWORD_STORE_UMASK, 077 by default (Executor::setChildUmask()): what they create in the store is then the user's alone, as with pass. static

The variables that keep git in store's own repository, never one above it: GIT_CEILING_DIRECTORIES (gitCeiling()), and, when that ceiling holds git's list separator (":", ";" on Windows) and so cannot be one entry of the list, GIT_DIR and GIT_WORK_TREE naming the store's own .git and the store. A store without a .git then has no repository to git, rather than the one above it.

An explicit GIT_DIR skips git's ownership check, which runs only when git discovers a repository. On Unix the store is therefore pinned only when git's check would pass: it, its .git and a gitfile's target are the user's own, or git's safe.directory names the store (as git reads it: only from system, global and command-line configuration, never a repository's own; *, an exact path, or a path ending in a slash and * for what lies below it, an empty value clearing the entries before it). Otherwise GIT_DIR names a path that cannot exist, and git refuses rather than run another user's repository and hooks.

Parameters
storeThe store's path.
gitThe git executable that reads safe.directory; "git" from PATH when empty. Run only for a store that is not the user's own.
asUserThe user to compare owners with; the effective user when not given (a test passes another).
Returns

◆ isLaunchableWebUrl()

auto Util::isLaunchableWebUrl ( const QString & value) -> bool
static

Check whether a value is a safe, launchable web URL.

Stricter than protocolRegex(): intended to gate an "open in browser" action, where launching a non-web scheme would be a security risk. Returns true only when the trimmed value:

  • contains no control characters (CR, LF, NUL),
  • parses to a valid QUrl,
  • has scheme exactly "http" or "https" (case-insensitive),
  • has a non-empty host,
  • carries no embedded userinfo (user:password@host).

Deliberately rejects file://, javascript:, data:, ftp/ssh/webdav and scheme-less inputs (e.g. "www.example.com").

Parameters
valueCandidate URL string (typically a password-file field).
Returns
true if the value is a launchable http(s) URL, false otherwise.

◆ regularFilesUnder()

auto Util::regularFilesUnder ( const QString & dir,
const QStringList & nameFilters,
QStringList * skipped = nullptr,
bool hiddenFiles = false ) -> QStringList
static

Regular files under dir whose name matches one of nameFilters, found by walking only real directories.

Symbolic links and NTFS junctions are never entered and never listed: either can point outside the tree, and QDirIterator's own recursion treats a junction as an ordinary directory (Qt marks it JunctionType, not LinkType, so QDir::NoSymLinks does not see it). Hidden directories (.git, a sync tool's version folder) are not entered either, as with QDirIterator without QDir::Hidden.

dir itself is followed whatever it is: the configured store root is commonly a symlink (~/.password-store to a synced folder), and it is the user's choice, not something found inside the store. A caller that gets its folder from the store tree decides with isLinkedFolder() first.

The walk is a listing, not a lock: what is a regular file when listed can be replaced before it is opened. That is the store's trust boundary (SECURITY.md), not something a walk can close.

Parameters
dirDirectory to walk.
nameFiltersWildcards, as for QDir::setNameFilters().
skippedReceives what was left out although it is in the way: every linked directory, and every link or special file (FIFO, socket, device) whose name matches nameFilters. Null to not care.
hiddenFilesList hidden files too (.gpg-id); hidden directories stay closed regardless.
Returns
Absolute paths, sorted by name within each directory, a directory's files before its subdirectories.

Flush file's bytes to the device (fsync, FlushFileBuffers) before it is renamed into place, so that a crash right after the rename does not leave the name pointing at an empty file. QSaveFile did this on commit; the staged writes here do it themselves.
