Detailed Description

Runs non-interactive external commands in FIFO order using a single QProcess.

Queues execution requests and emits per-request completion or error signals; supports optional stdin, configurable stdout/stderr capture, and per-request working directory and environment.

Emitted, synchronously, when the queue's head leaves it: just before it is started, when it cannot be (no executable, a failed start), or when cancelNext() drops it. Lets a caller do per-item work at the moment the item actually runs, not when it was queued.

Parameters
idThe item's id.
completesWhether finished() or error() follows for it: for every item but one cancelNext() dropped. Those that complete do so in the order they left the queue.

A slot may queue more with execute(): that waits behind this item. The executor counts as running while the signal is out, also for an item cancelNext() drops, so cancelNext() drops nothing then (-1) and nothing starts until the signal has returned.

auto Executor::executeBlocking ( QProcess & process,
const QString & app,
const QStringList & args,

const std::atomic_bool * cancel = nullptr,
int timeoutMs = -1 ) -> int
staticnodiscard

Run a command synchronously on a caller-supplied QProcess, with optional cancellation.

The caller configures process (environment, say) before the call; it must be a fresh, not yet started object. QProcess is not thread-safe, so process belongs to the calling thread for the whole run: no other thread may call terminate(), kill() or anything else on it. To let a run be cancelled, pass cancel: the wait then polls the flag, and once it is set the calling thread itself terminate()s the child, waits a short grace period, kill()s it if it is still running, waits one more grace period at most, and returns -1. Setting the flag is the only thing another thread does; it may do so at any time, before or during the run. A run given timeoutMs ends the same way once that time has passed, start included, so it returns within the timeout plus twice the grace even when a kill()ed child cannot exit yet (uninterruptible sleep on a hung mount). Not timed: QProcess::start() itself, which can block, for example opening a FIFO named by a redirected channel (no caller redirects one), and QProcess's destructor, which still waits for such a child, for up to 30 s.

Parameters
processProcess object to run the command on.
appExecutable path.
argsCommand arguments.
inputData to write to stdin.
process_outIf non-null, receives stdout output.
process_errIf non-null, receives stderr output.
cancelIf non-null, a flag that ends the run when set.
timeoutMsTime for the whole run, start included; negative (the default) for none.
Returns
Process exit code, or -1 if it failed to start, crashed, was cancelled or ran out of time.

◆ parseWslCommand()

auto Executor::parseWslCommand ( const QString & app) -> std::optional< WslCommand >
static

Parse a configured executable as a WSL command.

Accepts wsl or wsl.exe in any case, bare or as a path, followed by wsl.exe options and exactly one program: wsl gpg, WSL.EXE -d Debian /usr/bin/gpg, C:\Windows\System32\wsl.exe -u me gpg. A -e/--exec the user wrote is dropped (argv() adds it), anything after the program (wsl sh -c "gpg") or a wsl with no program is not a WSL command.

Every place that starts, probes or translates paths for a configured executable goes through this, so a form one of them accepts cannot be started differently by another.

Parameters
appExecutable as configured.
Returns
The parsed command, or nothing when app is not one.

auto Executor::resolveExecutable ( const QString & app) -> QString
static

The one rule for turning a configured executable into what runs.

Absolute paths and "wsl ..." commands are used as given. A bare or relative name is looked up next to the application first (the Windows and macOS bundles ship gpg/git/pass there) and otherwise left for QProcess's PATH lookup. Both the queued and the blocking path go through this, so the same setting can no longer run two different binaries.

Shared blocking run: start process, optionally feed input on stdin, wait, and capture stdout/stderr. Backs the executeBlocking overloads. The caller configures process (e.g. environment) first.

With a null cancel the wait is a plain waitForFinished(-1). With a non-null one the wait polls the flag; once it is set this thread terminate()s the child, gives it a short grace period, kill()s it if it is still running, waits one more grace period at most, and returns -1. A flag that is already set skips the start altogether.

Returns

The umask every child QtPass starts gets, as pass sets its own.

pass runs git and gpg under umask 077 (or PASSWORD_STORE_UMASK), so the folders and files they create in the store, .git included, are the user's alone.
