Detailed Description

Turn a directory into a password store without going through the Pass backend of the currently active store.

The backend is a shared singleton bound to the active store (settings snapshot, PASSWORD_STORE_DIR, one FIFO of asynchronous processes), so a new profile cannot be initialised through it without racing the active store (#1774). Everything here is synchronous and touches only dir.

const AppSettings & s,
bool useGit,
QString * note ) -> bool
static

Write the recipients and, if wanted, put the folder under git.

Writes <dir>/.gpg-id with the enabled key ids, signs it when s.passSigningKey is set, and when useGit runs git init, git add and git commit inside dir with blocking processes. Existing *.gpg files are left alone: re-encrypting them needs the backend, i.e. the profile has to be the active store; note says so.

Parameters
dirDirectory to initialise; created if missing.
usersKey list; only entries with enabled == true are written.
sSettings for the gpg/git executables and the signing key.
useGitWhether to create a repository and commit the file.
noteReceives a translated message for the user (empty on a quiet success): the error, or the warning about existing entries.
Returns
true when the .gpg-id (and signature/commit if requested) is in place.
