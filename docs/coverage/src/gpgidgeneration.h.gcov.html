      17              :  * @brief Rollback detection for signed `.gpg-id` files.
      18              :  *
      19              :  * A signature proves that a recipient list is authentic and unmodified; it
      20              :  * does not prove that it is the current one, nor that it was written for
      21              :  * the folder it sits in. Whoever can write to a shared store can put back an
      22              :  * older, genuinely signed list that still names a member since removed, or
      23              :  * copy such a pair into a folder that never had a list of its own, and every
      24              :  * later encryption there would include them again.
      25              :  *
      26              :  * So a `.gpg-id` QtPass writes for a store with a signing key starts with
      27              :  * three comment lines, `# QtPass-GpgId-Generation: N`,
      28              :  * `# QtPass-GpgId-Folder: <store-relative folder>` and
      29              :  * `# QtPass-GpgId-Store: <store id>`, which `pass` (1.7.4 and later),
      30              :  * QtPass (1.8 and later) and QtPass's own recipient parser ignore and the
      31              :  * signature covers. The store id binds the list to its store, as the folder
      32              :  * line binds it to its folder: one signing key may sign several stores, and
      33              :  * a list of one copied into another at the same folder would verify there
      34              :  * too (#2050). Each device remembers the id it first saw per store and
      35              :  * refuses a list of another store, or a new list without the line. QtPass
      36              :  * remembers, per `.gpg-id` file, the highest generation it has accepted or
      37              :  * written, and refuses a signed list whose generation is lower or whose folder
      38              :  * is not the one it sits in. Stores without a signing key get plain lists, as
      39              :  * before: nothing checks their freshness, and older clients (pass up to 1.7.3,
      40              :  * Android Password Store) take a comment for a recipient.
      41              :  *
      42              :  * What this is and is not: rollback detection on a device that has seen the
      43              :  * newer list. A device seeing a store for the first time, or one that was
      44              :  * offline, has nothing to compare against. The generation is monotonic per
      45              :  * observer, not a distributed sequence number: two devices can both produce
      46              :  * generation 19 from 18, and Git is what sorts that out; a device that
      47              :  * accepted one of the two then meets the other as the same generation with
      48              :  * different bytes, which is a conflict, not a rollback, and is refused until
      49              :  * a holder of the signing key saves the recipients once more. For that the
      50              :  * record keeps, next to the generation, a digest of the exact bytes it
      51              :  * accepted or wrote. A list without the lines (written by `pass`, or by

      54              :  * QtPass writes the next generation. Without a readable and writable record
